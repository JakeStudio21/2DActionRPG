## 1. 시스템 개요

### 1.1 목적

장비 강화 시스템을 통해:
- **플레이어 성장 목표 제공**: 장비를 통한 단계적 파워업
- **엔드게임 콘텐츠**: 최상위 강화 도전 목표
- **재화 소모처**: 골드와 재료의 균형 있는 소비
- **리스크-리워드**: 실패 위험성을 통한 긴장감 제공

### 1.2 강화 대상

- ✅ **무기 (Weapon)**: 공격력, 크리티컬 증가
- ✅ **방어구 (Armor)**: 방어력, 체력 증가
- ✅ **악세사리 (Accessory)**: 특수 스탯 증가

### 1.3 강화 범위

- **최소 레벨**: +0 (기본 상태)
- **최대 레벨**: +15 (최종 강화)
- **총 단계 수**: 16단계

## 2. 핵심 설계 원칙

### 2.1 책임 분리 (Separation of Concerns)

강화 시스템은 **2개의 독립적인 테이블**로 구성:

```
┌─────────────────────────────────┐
│  EnhanceLevelTableSO            │  → "강화 시도 자체의 규칙"
│  - 비용 (골드, 재료)             │
│  - 확률 (성공률)                 │
│  - 보너스 트리거                 │
│  - 실패 타입 (유지/하락/파괴)    │
└─────────────────────────────────┘

┌─────────────────────────────────┐
│  EnhanceCurveTableSO            │  → "강화했을 때 얼마나 강해지는가"
│  - 스탯 증가율                   │
│  - 성장 곡선                     │
│  - 장비 타입별 커브              │
└─────────────────────────────────┘
```

### 2.2 데이터 중심 설계 (Data-Driven)

- **ScriptableObject 기반**: Unity Inspector에서 실시간 조정 가능
- **코드 수정 불필요**: 밸런스 패치 시 데이터만 변경
- **확장성**: 새로운 곡선(이벤트 강화 등) 추가 용이

### 2.3 V2 인벤토리 연동

- **ItemInstanceId 기반**: 각 아이템은 고유 ID로 관리
- **계정 공유 인벤토리**: AccountDataManager 통합
- **골드 V2 시스템**: 계정 공유 골드 (PlayerDataManager.SpendGold)

### 5.2 실패 처리 타입

#### **Type 1: 레벨 유지 (Maintain)**
- **적용 구간**: Lv 1~9
- **효과**: 강화 레벨 변동 없음
- **소모**: 재료 + 골드 소모됨
- **플레이어 영향**: 낮음 (안전)

#### **Type 2: 1단계 하락 (Downgrade)**
- **적용 구간**: Lv 10~12
- **효과**: 현재 레벨 -1 (최소 0)
- **소모**: 재료 + 골드 소모됨
- **플레이어 영향**: 중간 (재도전 필요)

**예시:**
```
+11 강화 실패 → +10으로 하락
+10 강화 실패 → +9로 하락
```

#### **Type 3: 아이템 파괴 (Destroy)**
- **적용 구간**: Lv 13~15
- **효과**: **아이템 완전 소멸** 💥
- **소모**: 재료 + 골드 소모됨 + 아이템 소실
- **플레이어 영향**: 매우 높음 (복구 불가)

**경고 시스템:**
```
⚠️ [경고] 아이템 파괴 위험!
━━━━━━━━━━━━━━━━━━━━━━
  현재 강화: +13
  성공률: 40%
  
  ⚡ 실패 시 아이템이 완전히
     파괴되어 복구할 수 없습니다!
     
  [ 강화 진행 ] [ 취소 ]
```

### 5.3 성공/실패 판정

**판정 로직:**
```csharp
float successRate = LevelTable.GetSuccessRate(targetLevel); // 0~100%
float randomValue = Random.Range(0f, 100f);

if (randomValue <= successRate)
{
    // 성공: 레벨 +1
    itemData.enhancementLevel++;
}
else
{
    // 실패: 타입별 처리
    var failureType = LevelTable.GetFailureType(targetLevel);
    
    switch (failureType)
    {
        case Maintain:    // 유지
        case Downgrade:   // -1 하락
        case Destroy:     // 아이템 파괴
    }
}
```

## 6. 스탯 증가 시스템

### 6.1 성장 곡선 (3가지)

#### **CURVE_WEAPON (무기 곡선)**

| **Lv 6~10** | +2.0% | +10.0% | +17.5% |
| **Lv 11~15** | +3.0% | +15.0% | **+32.5%** |

### 6.2 스탯 증가 적용 방식

**공식:**
```
최종 스탯 = 기본 스탯 × (1 + 누적 증가율)
```

**예시: 공격력 120인 무기 +12 강화**
```
기본 공격력: 120
누적 증가율: 17.5% + (2.0% × 2) = 21.5%
최종 공격력: 120 × (1 + 0.215) = 145.8
```

**적용 대상 스탯:**
- 무기: `attackDamage`, `criticalChance`, `criticalDamage`
- 방어구: `defenseBonus`, `healthBonus`
- 악세사리: 모든 보너스 스탯

## 7. 보너스 시스템

### 7.1 구간 보너스 (Milestone Bonus)

특정 강화 레벨 달성 시 **추가 효과** 부여:

| 강화 레벨 | 보너스 ID | 효과 (기획 예시) |
|----------|-----------|-----------------|
| **+3** | BONUS_LV3 | 크리티컬 확률 +1% |
| **+6** | BONUS_LV6 | 크리티컬 데미지 +5% |
| **+9** | BONUS_LV9 | 공격 속도 +3% |
| **+12** | BONUS_LV12 | 스킬 쿨다운 -5% |
| **+15** | BONUS_LV15 | 모든 스탯 +2% (추가) |

### 7.2 보너스 적용 시점

**획득 조건:**
- 해당 강화 레벨 **성공 시** 자동 적용
- 레벨 하락 시에도 보너스 유지 (예: +12 → +11 하락해도 BONUS_LV12 유지)

**UI 표시:**
```
┌─────────────────────────────┐
│  Sword of Flames +12        │
├─────────────────────────────┤
│  공격력: 145.8 (+21.5%)     │
│  크리티컬 확률: 10% → 11%   │ ← BONUS_LV3
│  크리티컬 데미지: 1.5x → 1.55x │ ← BONUS_LV6
│  공격 속도: +3%              │ ← BONUS_LV9
│  스킬 쿨다운: -5%            │ ← BONUS_LV12
└─────────────────────────────┘
```

### 7.3 보너스 확장 가이드

**추가 가능한 보너스 타입:**
- 속성 부여 (화염, 독, 얼음)
- 특수 효과 (흡혈, 관통, 범위 공격)
- 세트 효과 연동 (같은 세트 +12 이상 시 추가 보너스)

## 8. 재료 시스템

### 8.1 재료 획득

**드롭 시스템 연동:**
```csharp
// 몬스터 처치 시
ItemDrop → MaterialType 확정
         → AccountDataManager.AddMaterial(type, count)
```

**예상 드롭률 (기획 가이드):**

| 몬스터 타입 | 재료 종류 | 드롭률 | 평균 개수 |
|-----------|-----------|--------|----------|
| 일반 몬스터 | Fragment | 10% | 1~2개 |
| 엘리트 몬스터 | Fragment | 30% | 2~3개 |
| 엘리트 몬스터 | Crystal | 5% | 1개 |
| 보스 몬스터 | Crystal | 30% | 3~5개 |
| 보스 몬스터 | Core | 10% | 1~2개 |

### 8.2 재료 저장

**V2 인벤토리 연동:**
- 계정 공유 재료 (AccountData.materials)
- 캐릭터 삭제해도 재료 유지
- Dictionary<MaterialType, int> 구조

**저장 위치:**
```
AccountData {
  materials: {
    WeaponFragment: 50,
    WeaponCrystal: 10,
    WeaponCore: 2,
    ...
  }
}
```

### 8.3 재료 소모

**강화 시스템 호출:**
```csharp
MaterialType materialType = GetRequiredMaterialType(equipmentType, itemGrade);
int materialAmount = LevelTable.GetMaterialCount(targetLevel);

if (!AccountDataManager.RemoveMaterial(materialType, materialAmount))
{
    // 재료 부족
    return;
}
```
